# Design context

This file is the source of truth for design decisions in this project. Before
writing UI code, read this file and align with the principles below.

## Design Context

### Users

Backend Python developers working on SQLAlchemy + Alembic codebases. They open
the schema viewer to **answer specific questions** ("where does this FK point?",
"what's the latest migration?", "what columns does `bookings` have?") — they
are not browsing for inspiration. Sessions are short, focused, and often
interleaved with terminal work. Many will project the screen during pair
programming or design reviews.

Skill ceiling: high. Patience for chrome: low. They prefer a tool that respects
their attention.

### Brand Personality

**Quiet, technical, precise.**

- Voice: terse, accurate, useful. Microcopy reads like good docstrings — not
  marketing. No exclamation marks. No emoji. No "Awesome!" or "Oops!".
- Tone is *kind* — gentle empty states, helpful errors, never blaming the user.
- Confidence comes from restraint, not assertion.

Reference apps that capture the right feel: **Drizzle Studio, Linear,
Vercel dashboard, Raycast (the calm parts).**

### Aesthetic Direction

- **Design system**: shadcn/ui visual language — neutral foundation, subtle
  borders, soft radii, restrained shadows. Lucide-style line icons.
- **Theme**: light and dark, user-switchable anytime, with a persistent toggle
  in the top bar. Default to OS preference (`prefers-color-scheme`) on first
  load; remember the user's manual override in `localStorage`.
- **Density**: comfortable — ~26px row height in table cards, tables readable
  at 1.0 zoom without leaning in.
- **Motion**: minimal and functional — fades and small transforms only.
  Honor `prefers-reduced-motion`.
- **Typography**: system sans (`-apple-system, Inter, Segoe UI`) for chrome;
  monospace (`ui-monospace, SF Mono, Menlo`) for column names, types, and
  revisions. No display fonts.

#### Anti-references — explicitly avoid

- **Bloated enterprise tool**: no busy toolbars, no nested tabs, no modal
  pyramids, no settings page that's another app.
- **Generic admin dashboard**: no Bootstrap-y blue buttons, no card grids
  with random colored top-borders, no obligatory "Welcome, user" header.
- **Marketing-site aesthetic**: no hero, no gradients-for-mood, no
  illustrations, no animated entrance sequences.

### Design Principles

1. **Data first, chrome last.** Every pixel of UI must justify itself against
   the schema diagram. If a control is used once a session, demote it.
2. **One way to do each thing.** No duplicated affordances (sidebar + canvas +
   command palette doing the same job). Choose the most direct path.
3. **Never block the read path.** Loading and error states reveal partial
   data instead of full-screen spinners. The diagram is the product.
4. **Be kind in failure.** Errors describe what happened in plain language and
   suggest a next step. Never paste a stack trace at the user.
5. **Respect environment.** Dark mode is not an afterthought. Reduced motion
   is honored. Tab order works. The tool feels native to the terminal it
   lives next to.
